# 如何离开科研界：科研能力转化、求职策略与针对性简历

`tailor-job-resume` 是一套面向科研人员、研究生及准备从学术研究转向业界的skill。

它提供两个功能：

1. 没有目标岗位时，从综合简历和论文出发，研究求职者会什么、能去哪里、市场上有哪些岗位以及大致薪资。
2. 已有具体岗位时，在同一套能力证据基础上生成单位与岗位专属的可编辑HTML简历。

## 模式一：职业探索

### 职业探索固定触发语句

> 请根据我的履历制定求职策略

适合还不知道自己能进入哪些行业、应该搜索什么岗位或市场薪资如何的用户。

### 用户需要提供

- 综合简历。
- 输出目录。

论文全文、项目报告、作品和照片均为可选。用户不需要提供具体岗位，也不需要预先整理DOI、摘要、招聘数据或薪资数据。

### 系统会做什么

1. 从综合简历识别全部论文和研究项目。
2. 自动查找DOI、期刊官网、摘要、全文、官方PDF和合法公开版本。
3. 逐篇阅读全文、附录和补充材料，审计数据、价值评估方法、模型、算法、软件、参数、验证、分析流程和成果。
4. 把科研能力翻译成企业能够理解的工作能力。
5. 让用户确认哪些能力有直接证据、哪些由方法关系推出、哪些需要本人补充确认。
6. 主动识别全部有依据的职业方向，不要求用户预先选择行业、企业性质、城市或薪资。
7. 逐个方向搜索近期公开岗位，研究工作内容、招聘需求和薪资。
8. 生成完整的职业方向、岗位关键词和求职策略报告。

### 交付物

职业探索模式只生成一个用户可见文件：

```text
姓名_求职决策中心.html
```

它把能力确认、能力证据、论文方法与数据审计、职业方向、岗位关键词、招聘市场、薪资和行动计划整合在一个页面中。结构化数据嵌入HTML内部，供以后申请具体岗位时复用，用户不需要打开JSON或Markdown。

职业探索模式不生成某家单位的专属简历，因为没有具体招聘要求时无法真正做到单位与岗位定制。

## 模式二：岗位定制

### 岗位定制固定触发语句

> 请根据这个岗位帮我制作针对性简历

适合已经找到具体招聘岗位、准备正式投递的用户。

### 用户需要提供

- 综合简历。
- 具体岗位信息，包括单位、岗位名称、职责和任职要求。
- 输出目录。

照片和参考模板可选。如果用户已有同一求职者的求职决策HTML，Skill会先读取其中的结构化数据；材料有变化时再补充分析。

### 系统会做什么

1. 拆解具体岗位的硬性门槛、核心职责、业务能力、方法工具和优先条件。
2. 将岗位要求与已经确认的履历证据逐项对应。
3. 选择最有说服力的经历，调整排序和企业化表达。
4. 继续研究相关职业方向和市场薪资，让具体投递不脱离更广泛的求职策略。
5. 生成可直接编辑、打印和导出PDF的岗位专属HTML简历。

### 交付物

```text
姓名_单位_岗位_求职决策.html
姓名_单位_岗位_简历.html
```

求职决策HTML适合本人阅读，包含匹配证据、能力缺口、薪资、简历取舍和面试策略；简历HTML用于对外投递。两者都可以直接编辑、保存并导出PDF。
对话中还会提供一段结合履历和岗位要求的个人总结。

## 从论文中识别真正的职业能力

本Skill会根据论文主题匹配岗位，然后继续分析：

- 数据类型、来源、规模、时间跨度和空间范围。
- 数据清洗、匹配、指标构建和质量检查。
- 研究设计、统计方法、模型、算法和验证方法。
- 软件、编程语言、程序包、数据库和制图工具。
- 从提出问题到解释结果、可视化和报告交付的完整流程。

例如：

- GIS和空间计量可以迁移到地图、LBS、商业选址、物流和城市计算。
- DID可以迁移到政策、活动或业务措施的效果评估。
- 聚类分析可以迁移到用户分群、区域分类和市场细分。
- XGBoost和SHAP可以迁移到预测分析、关键因素识别和模型解释。

如果求职者是第一作者、共同第一作者或通讯作者，论文全文中实际执行的数据、模型、方法、软件和分析流程默认由本人使用，并按熟练能力处理；用户可以指出例外。其他署名作者仍需根据作者贡献、简历描述或本人确认判断。

## 论文资料由Skill优先查找

综合简历只要包含论文题目，系统就会自动尝试查找：

- DOI
- 期刊官网文章页
- 摘要和关键词
- HTML全文或官方PDF
- 补充材料或合法公开版本

只有公开渠道仍无法获得全文时，才请求用户上传。

DOI只是定位论文的入口，不是检索终点。找到DOI后仍须阅读方法、数据、结果、附录和补充材料；不能用摘要级提取冒充全文审计。

## 三级事实确认

最终呈现结果前会集中展示：

- A级：简历、论文或项目材料直接证明。
- B级：由已确认方法的定义或必要关系直接推出，并说明理由。
- C级：可能具备但材料无法证明，必须由本人确认。

用户只确认事实，不负责预先决定职业方向。未确认的推测不会写进简历。

例如，论文明确使用SHAP时，可以说明使用了基于Shapley值的解释方法；但不能据此声称独立开发过Shapley算法。使用XGBoost也不能自动证明使用过Python。

## 完整职业边界与薪资研究

系统会把方向分为：

- 优先尝试：当前履历可以直接支撑。
- 值得拓展：研究主题不同，但方法、数据或软件能力可以迁移。
- 求职边界：补充少量能力或作品后有机会进入。
- 暂不建议：当前缺少关键门槛，转型投入较大。

识别出几个方向，就研究几个。系统不会因为用户暂时不了解民营企业、陌生行业或新岗位而提前排除。

招聘研究优先使用近期公开招聘页面、企业官网和招聘公告。

薪资说明会尽量注明城市、时间、样本数量、月薪或年薪和信息来源。岗位样本不足时会说明只能作为初步参考，不制造看似精确的数字。

## 针对性HTML简历

岗位定制模式生成的HTML支持：

- 直接编辑文字并自动暂存。
- 编辑与预览切换。
- 撤销全部修改。
- 下载修改后的HTML。
- 打印或导出PDF。
- 调整照片宽度、高度、位置和裁切。

论文统一为：

```text
标题或省略标题｜DOI｜期刊名称（等级）｜第几作者｜年份
```

DOI只显示为可点击的 `DOI` 三个字母。标题过长时自动缩短，其他信息保持完整；标题贴齐左侧，年份贴齐右侧。

## 通俗的求职策略报告

报告像职业顾问面对面解释，首页先回答：

- 最值得尝试什么。
- 还可以尝试什么。
- 哪些方向目前不建议。
- 大致可以争取什么薪资。
- 下一步最应该做什么。

随后逐个方向说明真实工作、匹配证据、招聘市场、薪资、能力缺口、简历写法、面试重点和补强建议。校验脚本会拦截缺少关键章节或典型学术化表达的报告。

## 事实与隐私边界

- 不将参与改成主持。
- 不将协助改成独立负责。
- 不虚构数据、软件、奖项、项目级别、论文状态或工作年限。
- 不把团队成果无条件归为个人成果。
- 除第一作者、共同第一作者或通讯作者适用的固定归属规则外，不把论文出现的相关方法自动写成熟练掌握。
- 不能确认的内容进入待确认清单，而不是直接写进简历。

真实简历、论文全文、照片、能力证据库和求职输出不得写入Skill目录或公开仓库。本仓库只包含通用规则、脚本和虚构示例。

## 输出格式与使用方式

默认交付格式只有HTML：

- `求职决策中心.html`或`求职决策.html`供求职者本人查看，集中保存能力证据、论文审计、职业边界、市场与薪资研究、行动建议等内部判断。
- `简历.html`供招聘单位查看，只保留真实、已确认且与岗位相关的对外信息，不写入能力缺口、薪资判断、投递取舍或面试风险。

HTML可以直接编辑、自动暂存、下载更新后的副本，并通过浏览器的打印功能导出PDF。因此，流程默认不重复生成PDF、Word、Markdown或独立JSON。用于后续复用的结构化数据保存在HTML内部的 `career-data` 区域，普通用户无需查看或维护。

## 兼容性与安装

核心流程由 `SKILL.md`、Markdown规则和Python脚本组成，业务逻辑并不依赖某一个模型或单一AI产品。具备以下能力的AI Agent通常可以移植或改造使用：

- 加载项目级指令或Skill文件。
- 读取DOCX、PDF、HTML等本地材料。
- 访问公开网页并检索论文与招聘信息。
- 运行Python脚本并写入用户指定目录。

不同平台的自动触发、工具权限、联网方式和Skill安装目录可能不同，因此不能保证下载后在所有AI产品中原样运行。将仓库提供给支持项目指令或Skill机制的AI Agent，并让其以 `SKILL.md` 作为主流程入口；再按目标平台调整安装目录、触发方式和工具权限即可。`agents/openai.yaml` 是其中一种适配清单，不影响核心规则和Python脚本在其他环境中复用。

安装或更新后，请按所用平台的方式重新加载Skill。仅更新GitHub仓库不会自动覆盖此前下载到本地的副本，本地版本需要重新拉取、重新安装或手动同步。
