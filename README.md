# 如何逃离科研界？
你需要科研能力转化、求职策略与针对性简历

`tailor-job-resume` 是一套面向科研人员、研究生及准备从学术研究转向业界的可复用AI工作流。

它提供两个入口：

1. 没有目标岗位时，从综合简历和论文出发，研究求职者会什么、能去哪里、市场上有哪些岗位以及大致薪资。
2. 已有具体岗位时，在同一套能力证据基础上生成单位与岗位专属的可编辑HTML简历。


## 两个固定触发语句

### 职业探索

> 请根据我的履历制定求职策略

适合还不知道自己能进入哪些行业、应该搜索什么岗位或市场薪资如何的用户。

### 岗位定制

> 请根据这个岗位帮我制作针对性简历

适合已经找到具体招聘岗位、准备正式投递的用户。

只有用户明确输入以上任一完整句子时才进入对应工作流。普通简历咨询、文字润色、岗位分析和HTML编辑不会启动完整流程。

## 模式一：职业探索

### 用户需要提供

- 综合简历。
- 输出目录。

论文全文、项目报告、作品和照片均为可选。用户不需要提供具体岗位，也不需要预先整理DOI、摘要、招聘数据或薪资数据。

### 系统会做什么

1. 从综合简历识别全部论文和研究项目。
2. 自动查找DOI、期刊官网、摘要、全文、官方PDF和合法公开版本。
3. 提取数据、方法、模型、算法、软件、分析流程和成果。
4. 把科研能力翻译成企业能够理解的工作能力。
5. 让用户确认哪些能力有直接证据、哪些由方法关系推出、哪些需要本人补充确认。
6. 主动识别全部有依据的职业方向，不要求用户预先选择行业、企业性质、城市或薪资。
7. 逐个方向搜索近期公开岗位，研究工作内容、招聘需求和薪资。
8. 生成完整的职业方向、岗位关键词和求职策略报告。

### 交付物

```text
输出目录/
├── 能力确认表.md
├── 能力证据库.json
├── 职业方向与岗位关键词.md
└── 求职策略报告.md
```

`能力证据库.json` 用于在以后申请具体岗位时复用已经确认的事实，避免重复分析和重复提问。它包含个人材料，只能保存在用户指定目录，不能上传到公开仓库。

职业探索模式不生成某家单位的专属简历，因为没有具体招聘要求时无法真正做到单位与岗位定制。

## 模式二：岗位定制

### 用户需要提供

- 综合简历。
- 具体岗位信息，包括单位、岗位名称、职责和任职要求。
- 输出目录。

照片和参考模板可选。如果输出目录已经存在同一求职者的 `能力证据库.json`，Skill会先复用；材料有变化时再补充分析。

### 系统会做什么

1. 拆解具体岗位的硬性门槛、核心职责、业务能力、方法工具和优先条件。
2. 将岗位要求与已经确认的履历证据逐项对应。
3. 选择最有说服力的经历，调整排序和企业化表达。
4. 继续研究相关职业方向和市场薪资，让具体投递不脱离更广泛的求职策略。
5. 生成可直接编辑、打印和导出PDF的岗位专属HTML简历。

### 交付物

```text
输出目录/
├── 姓名_单位_岗位_可编辑版.html
├── 岗位匹配分析.md
└── 求职策略报告.md
```

不会额外生成 `姓名_单位_岗位_针对性简历.html`。对话中还会提供一段结合履历和岗位要求的个人总结。

## 从论文中识别真正的职业能力

系统不会只根据论文主题匹配岗位，而会继续分析：

- 数据类型、来源、规模、时间跨度和空间范围。
- 数据清洗、匹配、指标构建和质量检查。
- 研究设计、统计方法、模型、算法和验证方法。
- 软件、编程语言、程序包、数据库和制图工具。
- 从提出问题到解释结果、可视化和报告交付的完整流程。

例如：

- GIS和空间计量可以迁移到地图、LBS、商业选址、物流和城市计算。
- DID可以迁移到政策、活动或业务措施的效果评估。
- 聚类分析可以迁移到用户分群、区域分类和市场细分。
- XGBoost和SHAP可以迁移到预测分析、关键因素识别和模型解释。

## 论文资料由Skill优先查找

综合简历只要包含论文题目，系统就会自动尝试查找：

- DOI
- 期刊官网文章页
- 摘要和关键词
- HTML全文或官方PDF
- 补充材料或合法公开版本

中文论文优先进入期刊官网，以完整题名查找文章详情页。普通搜索或Crossref没有结果时不会直接停止。只有公开渠道仍无法获得全文时，才请求用户上传。

## 三级事实确认

最终写作前会集中展示：

- A级：简历、论文或项目材料直接证明。
- B级：由已确认方法的定义或必要关系直接推出，并说明理由。
- C级：可能具备但材料无法证明，必须由本人确认。

用户只确认事实，不负责预先决定职业方向。未确认的推测不会写进简历。

例如，论文明确使用SHAP时，可以说明使用了基于Shapley值的解释方法；但不能据此声称独立开发过Shapley算法。使用XGBoost也不能自动证明使用过Python。

## 完整职业边界与薪资研究

系统会把方向分为：

- 优先尝试：当前履历可以直接支撑。
- 值得拓展：研究主题不同，但方法、数据或软件能力可以迁移。
- 求职边界：补充少量能力或作品后有机会进入。
- 暂不建议：当前缺少关键门槛，转型投入较大。

识别出几个方向，就研究几个。系统不会因为用户暂时不了解民营企业、陌生行业或新岗位而提前排除。

招聘研究优先使用近期公开招聘页面、企业官网和招聘公告，不要求用户自己写爬虫，也不要求提供招聘网站账号、密码或Cookie。

薪资说明会尽量注明城市、时间、样本数量、月薪或年薪口径和信息来源。岗位样本不足时会说明只能作为初步参考，不制造看似精确的数字。

## 针对性HTML简历

岗位定制模式生成的HTML支持：

- 直接编辑文字并自动暂存。
- 编辑与预览切换。
- 撤销全部修改。
- 下载修改后的HTML。
- 打印或导出PDF。
- 调整照片宽度、高度、位置和裁切。

论文统一为：

```text
标题或省略标题｜DOI｜期刊名称（等级）｜第几作者｜年份
```

DOI只显示为可点击的 `DOI` 三个字母。标题过长时自动缩短，其他信息保持完整；标题贴齐左侧，年份贴齐右侧。

## 通俗的求职策略报告

报告像职业顾问面对面解释，而不是写成论文。首页先回答：

- 最值得尝试什么。
- 还可以尝试什么。
- 哪些方向目前不建议。
- 大致可以争取什么薪资。
- 下一步最应该做什么。

随后逐个方向说明真实工作、匹配证据、招聘市场、薪资、能力缺口、简历写法、面试重点和补强建议。校验脚本会拦截缺少关键章节或典型学术化表达的报告。

## 事实与隐私边界

- 不将参与改成主持。
- 不将协助改成独立负责。
- 不虚构数据、软件、奖项、项目级别、论文状态或工作年限。
- 不把团队成果无条件归为个人成果。
- 不把相关方法自动写成熟练掌握。
- 不能确认的内容进入待确认清单，而不是直接写进简历。

真实简历、论文全文、照片、能力证据库和求职输出不得写入Skill目录或公开仓库。本仓库只包含通用规则、脚本和虚构示例。

## 兼容性与安装

核心流程由 `SKILL.md`、Markdown规则和Python脚本组成，业务逻辑并不依赖某一个模型或单一AI产品。具备以下能力的AI Agent通常可以移植或改造使用：

- 加载项目级指令或Skill文件。
- 读取DOCX、PDF、HTML等本地材料。
- 访问公开网页并检索论文与招聘信息。
- 运行Python脚本并写入用户指定目录。

不同平台的自动触发、工具权限、联网方式和Skill安装目录可能不同，因此不能保证下载后在所有AI产品中原样运行。仓库中的 `agents/openai.yaml` 和以下安装路径属于当前已验证的Codex适配；其他平台可以复用核心规则和脚本，并按各自机制调整入口或清单文件。

### 在Codex中安装

提出：

```text
请从GitHub安装这个Skill：https://github.com/Anastasia0521/tailor-job-resume
```

也可以下载仓库，将整个文件夹复制到：

```text
Windows: %USERPROFILE%\.codex\skills\tailor-job-resume
macOS/Linux: ~/.codex/skills/tailor-job-resume
```

安装或更新后，重新启动Codex或刷新Skills。

### 在其他AI Agent中使用

将仓库提供给支持项目指令或Skill机制的AI Agent，并让其以 `SKILL.md` 作为主流程入口。需要根据目标平台调整安装目录、触发方式和工具调用权限。Python脚本与 `references` 中的规则可以继续复用。
