# 输入与数据结构

## 必需输入

1. 岗位材料：单位、岗位名称、职责、任职要求。
2. 综合简历：至少包含可核验经历与基本联系方式。
3. 输出目录。

不要要求用户预先提供论文 DOI、摘要或全文。先根据综合简历中的论文题目自动检索；公开渠道仍找不到全文时再请求用户上传。

首次分析不要求用户选择行业、企业性质、城市、薪资或职业方向。系统先完成不设限的职业边界研究，用户只确认履历事实、方法软件和个人贡献。

## 可选输入与默认值

- 照片：缺少时生成无照片版，不使用虚构头像。
- 参考模板：缺少时采用正式、克制、A4 黑白研究/商业简历版式。
- 页数：未指定时按内容密度自动使用 2-3 页，不以缩小到不可读字号换取页数。
- 个人敏感字段：只保留用户明确提供且适合求职展示的字段。

## 构建脚本 JSON

```json
{
  "name": "示例姓名",
  "target": "示例单位｜示例岗位",
  "contact": ["电话：示例", "邮箱：example@example.com"],
  "summary": "针对性概述",
  "sections": [
    {
      "title": "岗位匹配能力",
      "items": [
        {"heading": "政策研究", "body": "以真实履历证据说明能力。"},
        {
          "kind": "paper",
          "title": "A verified full research paper title",
          "doi": "10.1234/example.2026.001",
          "doi_source_url": "https://journal.example.org/article/example",
          "journal": "Journal of Example Studies",
          "level": "SSCI",
          "author_rank": "第一作者",
          "year": "2026",
          "body": "说明本人的研究贡献和岗位价值。"
        }
      ]
    }
  ]
}
```

`sections[].items[]` 支持：

- `heading`：项目、经历或能力标题。
- `meta`：角色、机构和时间等简短信息，可省略。
- `body`：贡献说明。
- `kind: "paper"`：将条目标记为科研论文并启用 DOI 与单行标题处理。
- `title`：论文完整标题。生成器保留完整值，并根据渲染宽度生成显示标题。
- `doi`：仅填写已经出版社或 Crossref 等可信来源核验的 DOI；使用 `10.xxxx/...` 规范格式，不包含 `https://doi.org/` 前缀。
- `doi_source_url`：DOI 核验来源。中文论文优先填写期刊官网文章页或官网 PDF；该字段不显示在简历中。
- `journal`：期刊正式名称。
- `level`：论文或期刊等级，仅使用可核验信息。
- `author_rank`：求职者在论文中的署名顺序，如第一作者、第二作者或共同第一作者。
- `year`：发表年份或与论文状态一致的年份信息。

普通条目继续使用 `heading`。论文条目必须使用独立字段，不要把题目、DOI、期刊、等级、第几作者和年份手工拼接进 `heading` 或 `meta`。生成结果统一为单行，不显示完整作者名单。

`summary` 与所有 `body` 是简历描述正文，不得包含中文或英文引号、乘号 `×`、`✕` 或加号 `+`。论文题名等必须忠实保留的正式名称不受此限制。
