# 双入口模式

## 职业探索模式

仅由完整句子 `请根据我的履历制定求职策略` 触发。

必需输入只有综合简历和输出目录。岗位信息不是必需材料；缺少岗位时不得索要，也不得因此停止。执行论文检索、科研能力提取、事实确认、完整职业边界研究、招聘市场与薪资研究。

最终只交付 `姓名_求职决策中心.html`。能力确认、能力证据、论文方法数据审计、科研检索词、职业方向、岗位关键词和求职策略均整合并嵌入该HTML，不单独交付MD、JSON或PDF。

探索模式不生成单位与岗位专属简历。报告完成后，可以根据用户后续提供的具体岗位进入岗位定制模式。

## 岗位定制模式

仅由完整句子 `请根据这个岗位帮我制作针对性简历` 触发。

必需输入为综合简历、具体岗位信息和输出目录。缺少岗位信息时一次性说明缺少单位、岗位、职责或要求中的哪些内容，不要用市场上的相似岗位代替用户准备投递的岗位。

复用已有求职决策HTML中与当前求职者一致的 `career-data`。材料发生变化时补充分析，不重复询问已经确认的事实。

最终只交付 `姓名_单位_岗位_求职决策.html` 和 `姓名_单位_岗位_简历.html`。前者仅供本人阅读，后者可交给招聘方；不得混入彼此内容，也不单独交付MD、JSON或PDF。

## 共同规则

两个模式共享论文检索、能力提取、三级证据、事实边界、职业方向和市场研究规则。触发句决定模式；不要根据是否偶然附带岗位材料擅自改换模式。

所有结构化数据嵌入求职决策HTML的 `career-data` 区块，作为后续任务的复用入口。PDF由用户通过HTML内置打印功能按需导出，不作为默认重复交付物。
